## 2. Can Muse write a working program? (Q7, first look)

**Setup:**
- Model `muse-wonder-1.0` via `https://api.meta.ai/v1`, temperature 0.2.
- Prompt: the ASPIRE program rules + `docs/api-reference.md` + one example program for another task (`object_swap_seed1.py`) + the task text. No demo.
- Task `libero_goal_swap:8` "put the bowl on the plate", acceptance seed 51, seeded mode.
- Up to 2 repairs, with text feedback (outcome, the program's own report, names of failed calls).

Total: about 53k tokens, 3 calls. Prompt caching is active on the Meta API.

**Evidence lost.** The raw files of this run (the 3 programs, their run directories and the per-call token log) lived in the session's scratch folder, which was cleaned later the same day. The table above was written from them at the time. From now on, run evidence goes under the git-ignored `data/` folder.

**What went wrong (attempt 0, read from the program and the keyframe image):**
- The program grasps at the bowl's **centre** (x, y), 2 cm below the rim.
- The gripper comes down onto the bowl and stalls: the after-move keyframe shows the hand pressed on the bowl.
- hurobo found the same bowl must be grasped **by the rim** (hurobo design log D-010).
- So on this one case, a strategy a demo would show was not found from text and repair feedback.
- This is a single case and a hypothesis for the demo-vs-no-demo arms, not evidence yet.

**Also learned:**
- The feedback was too thin: failed-call names only. Next time, include the failure status, the target vs reached pose, and a text description of the keyframe.
- About 75–80% of the completion tokens are reasoning tokens.
