# ANTS System 1: module radar (2025–2026), 2026-10-31

Scope: candidate modules for System 1 (one video demo → DemoSpec → frozen code generator → plan gate → nominal replay), plus memory and escalation. Hardware: one RTX A5500 laptop GPU (16 GB), 62 GB RAM; APIs allowed; nothing trained. This note builds on `docs/synthesizer/discussion.md` §4 and §4.5 and on `docs/reuse-from-hurobo.md`, and says explicitly whether an existing pick still stands.

**Counts.** Cit. comes from the Semantic Scholar batch API and ★ from the GitHub API, both queried on 2026-10-31. The exceptions are ASPIRE and CaP-X, whose counts are copied from discussion.md (2026-10-28). Counts for 2026 papers change weekly. "–" means no public repo was found.
**Evidence tags.** **[read]**: the primary text was read. **[summary]**: a model-extracted summary of the paper's HTML or docs page. **[abstract]**: the arXiv abstract page or project page only. **[search summary]**: a search-engine snippet only, so treat it as unverified. Affiliations marked "(inferred)" come from author names, not from the paper. Numbers are the authors' own and were not reproduced.
**Fit.** 0 = skip, 3 = adopt now. **Tier.** hackathon = usable by 2026-11-04; research = after that.

**Headline.** **RAPID** (arXiv 2609.30249, MIT/NUS, 2026-09) already does "one demo → coding agent → verified program on reconstructed scene and variants". ANTS's novelty claim must be narrowed to the adaptive adversary, the monotone gate, memory with decay, and targeted-demo escalation. Second-biggest change: **Gemini Robotics-ER 2** replaced ER 1.x (1.6 shut down on 2026-08-31) and adds video moment finding and progress for keyframes.

**Recommendation.** Phase 1 (rendered LIBERO demo) needs no hand model: read the gripper aperture and EE pose from the simulator. For Phase 2 (tripod phone clip), **the existing picks HaMeR / WiLoR are still the best choice**, together with hurobo's MediaPipe TCP as a cheap fallback. No 2026 hand model has their traction: DewHand, InfiniHand and EgoFound3R target egocentric video and have 0–1 citations. Everything that closes the visual embodiment gap (Phantom, Masquerade, Ego2Robot, EgoZero, ZeroMimic) trains a policy. ANTS does not need it, because a code policy never sees the human image; say this in the pitch. Borrow one idea from NovaFlow and VideoManip: store the object's motion and pick the grasp as a separate, contact-consistent choice.

## Top 8 things to add to System 1 (ranked)

1. **Position against RAPID and copy its verification pattern** (B5/B8, hackathon). For each DemoSpec segment, have the generator write a success predicate. Generate bounded scene variants and have the agent write a feasibility filter. Reason: RAPID's scene variants alone moved success from 0.532 to 0.759, and the feasibility filter is the missing piece from discussion.md §10.4. Update the related-work section and the pitch so the ANTS delta is stated against RAPID, not only against ASPIRE.
2. **Hand DemoSpec to the generator as an RV-ICL-style queryable hierarchy** (B4/B5, hackathon). Expose keyframes, phase text, a moment index and short clips as read-only tools; do not put raw video in the prompt. Reason: on LIBERO it measured +3.9 points on PRO and +9.1 on Plus over text memory, and full video was worse than text. This is cheap to build from the simulator's gripper events.
3. **Gemini Robotics-ER 2 moment finding and progress as the keyframe extractor and second-opinion success signal** (B4/B8, hackathon if the user approves a Google key). Reason: it is the only off-the-shelf API that returns event timestamps. ER 1.x is gone, so fix the model IDs in the agentic-robot notes before reusing them. The benchmark predicate stays the only success signal for the gate.
4. **Memory admission as a gate: versioned constraints with non-regression on replay (Skill-V), plus re-verification at retrieval (SkillForge)** (B9, hackathon, design only). Reason: it reuses the regression-gate code, fixes ASPIRE's staleness problem, and makes "skills are shared" defensible. Cap the library size, since flat retrieval degrades past roughly 100 skills [search summary].
5. **ARCHITECT-style escalation: tie each human correction or targeted demo to code through the execution trace and store it as a skill** (B11/B9, research; the hackathon demo can use a scripted version). Reason: it is the closest working precedent, and targeted-demo escalation is still an open gap, so it is an ANTS contribution.
6. **Run the Q1 no-demo arm with at least two generator families** (B5, hackathon). Reason: LIBERO-Agent shows the value of a demo depends on the model (GPT-6 Astra 36 → 66%, Opus 8.3 → 5.8%). A demo effect measured on one model does not generalise, and Muse is a third, untested family.
7. **Phase 2 perception stack refresh: SAM 3.1 + Depth Anything 3 / MoGe-2 + HaMeR or WiLoR + FoundationPose or Any6D, with SpatialTrackerV2 for object 3D flow** (B1–B3, research). Reason: SAM 3.1 and HaMeR/WiLoR remain the best existing picks, while the depth picks (DA-V2, MoGe-1) are superseded. Everything fits 16 GB except SAM 3D Objects (32 GB).
8. **GraspGen + cuRoboV2 behind the existing primitive API** (B6, research). Reason: GraspGen is the maintained successor to Contact-GraspNet/M2T2, supports the Franka gripper and ships an MCP server, and cuRoboV2 is now Apache-2.0. Do not swap them before the hackathon, because the harness pins its own versions.

**Not worth adding:** world models as verifiers (WorldGym, Cosmos-Predict2.5, V-JEPA 2, DreamGen), human-video data engines that train policies (Phantom, Masquerade, Ego2Robot, EgoZero, ZeroMimic), VGGT-family multi-view reconstruction for a static tripod, and AnyGrasp (licence key).
